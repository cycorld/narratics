## 3. 내러틱스 6대 핵심 UX 개선 아키텍처

### 축 1. 타자기 중앙 스크롤 (Typewriter Scrolling) & 집중 몰입 모드 (Zen Mode)
* **문제점**: 긴 원고를 쓸 때 커서가 화면 하단으로 내려가 사용자의 목이 아래로 꺾이고 시선 집중이 흐트러짐.
* **해결책**:
  * 타이핑 시 커서가 위치한 줄이 항상 화면 수직 50% 높이에 고정되는 부드러운 타자기 스크롤링 엔진 구축.
  * `F9` 또는 상단 툴바 토글로 에디터 좌/우 패널을 숨기고 순수 원고에만 집중하는 Zen 모드 제공.

### 축 2. 도서 목표치 프로그레스 HUD & 일일 집필량 (Daily Delta) 트래커
* **문제점**: 전체 도서 목표치(예: 50,000자) 대비 현재 진행률을 알기 어렵고, 오늘 순수하게 몇 자를 썼는지 알 수 없어 집필 동기부여 저하.
* **해결책**:
  * 에디터 하단 상태바에 `[목표 50,000자 중 12,450자 (24.9%)]` 프로그레스 바 및 씬별 기여도 표시.
  * 오늘 세션 시작 이후 작성된 순수 증분 글자수(`오늘 집필량 +1,240자`)를 실시간 카운팅하여 표시.

### 축 3. 코르크보드 인덱스 카드 뷰 & 씬 개요 매트릭스 (Corkboard Mode)
* **문제점**: 트리 형태의 바인더 목록만으로는 각 씬의 시놉시스와 진행 상태(초고/수정중/퇴고/탈고)를 거시적으로 조망하기 어려움.
* **해결책**:
  * 스튜디오 상단에 `[원고 집필 뷰] / [코르크보드 개요 뷰]` 세그먼트 스위처 제공.
  * 코르크보드 선택 시 현재 챕터 하위의 씬들이 카드 형태로 3~4열 그리드로 배치되며, 시놉시스, 작성 상태, 글자수를 한눈에 확인하고 즉각 순서를 변경 가능.

### 축 4. 에디터 듀얼 분할 참조 뷰 (Split Screen Reference View)
* **문제점**: 3장 본문을 쓰면서 1장의 복선이나 인물 대사를 대조하려면 바인더를 왔다갔다 전환해야 해서 집중이 단절됨.
* **해결책**:
  * 에디터 우측에 "참조 뷰(Split Reference)" 토글을 두어, 현재 집필 창 옆에 다른 씬의 원고나 메모를 나란히 띄워두고 스크롤 대조 가능.

### 축 5. 퀵 로어 커맨드 팔레트 (`Ctrl+K`) & 인스펙터 연동
* **문제점**: 집필 도중 등장인물(예: '에이든')의 나이나 세부 설정을 확인하려면 마우스로 우측 인스펙터를 열고 스크롤해야 함.
* **해결책**:
  * `Ctrl+K` 단축키로 중앙 검색 팝업(Command Palette)을 띄워 로어 키워드를 타이핑하면 즉시 인스펙터 상세 카드로 점프.

### 축 6. 방어적 UX: 모달 없는 즉각 삭제 및 실행 취소 (Reversible Undo Toast)
* **문제점**: 씬이나 노드 삭제 시마다 브라우저 `confirm("정말 삭제하시겠습니까?")` 경고창이 떠 작업 리듬이 끊김.
* **해결책**:
  * 클릭 즉시 안전하게 휴지통(`trash`) 노드로 격리하고, 화면 하단에 5초간 `[제1장 씬이 휴지통으로 이동되었습니다. | 실행 취소 (Undo)]` 스낵바 제공.
  * '실행 취소' 클릭 시 원래 부모와 순서로 즉시 복원하여 스트레스 없는 안전한 편집 보장.

## 4. 사전 검증 및 반증 (Falsification & Safety Review)

1. **타자기 스크롤의 한글 조합(IME) 충돌 여부**:
   * *위험*: 자모 조합 중에 `scrollTop`이 강제로 이동하면 글자 분리 현상 발생 가능.
   * *방어*: `compositionstart` / `compositionend` 이벤트를 감지하여 한글 조합 중에는 스크롤 보정을 유예하고 조합 완료 또는 스페이스/엔터 시점에만 프레임 보정 적용.
2. **코르크보드 뷰와 Yrs CRDT 간의 상태 불일치 여부**:
   * *위험*: 코르크보드에서 씬을 조작할 때 실시간 웹소켓 이벤트 누락 가능성.
   * *방어*: 코르크보드는 독립적인 로컬 상태를 갖지 않고 단일 진실 공급원(`projectState.binder`)을 읽기 전용으로 구독하므로 100% 일치 보장.
3. **22개 자동화 회귀 게이트 보존**:
   * 모든 UI 확장은 기존 REST API 스키마(`MoveNodePayload`, `SceneUpdatePayload`)를 100% 재사용하며 서버 계약을 침범하지 않음.
